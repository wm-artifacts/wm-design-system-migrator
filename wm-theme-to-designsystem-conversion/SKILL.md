# /wm-theme-to-designsystem-conversion — Legacy Theme → Design Tokens Converter

Convert legacy WaveMaker theme `style.css` into structured design token overrides, component
variant JSON, and migrated icon fonts — ready for DesignSystem Studio import.

---

## What This Skill Produces

```
src/main/webapp/design-tokens/
├── app.override.css                    ← empty stub (Studio auto-generates from JSON)
├── icon.css                            ← @font-face + icon base selector + .pr-* classes ONLY
├── theme-style.css                     ← font @import + :root vars + component CSS for 11 core components
├── custom-icon/                        ← icomoon font files (co-located with icon.css)
│   ├── icomoon.eot
│   ├── icomoon.ttf
│   ├── icomoon.woff
│   └── icomoon.svg
└── overrides/
    ├── global/
    │   ├── color/
    │   │   ├── color.light.json        ← brand color overrides (light mode)
    │   │   └── color.dark.json         ← brand color overrides (dark mode, if applicable)
    │   ├── typography/
    │   │   └── typography.json         ← font family, h1-h6, body scale overrides
    │   └── spacing/
    │       └── spacing.json            ← border-radius and spacing scale overrides
    └── components/
        ├── button/
        │   └── button.json             ← custom button variant appearances
        ├── anchor/
        │   └── anchor.json
        └── <component>/
            └── <component>.json        ← one JSON per component, all variants inside
```

> **`app.override.css` is auto-generated by the design system from the JSON files — never create it manually.**
> **`icon.css` contains ONLY icon CSS — no component variants, no utility CSS.**
> **`theme-style.css` contains font `@import` + `:root` vars + CSS rules for button, label, anchor, cards, popover, container, panel, form, list, picture, tile — and their nested/custom-class combinations — plus all `@keyframes` animation blocks found in style.css.**

### STEP 2b · Build Component Selector Map from Foundation CSS

**Purpose:** Dynamically derive the CSS selector for each supported component by reading its
foundation-css token file. This selector is used in STEP 8 to detect custom variants in style.css.

#### Algorithm

```
For each component folder in <VARIANT_COMP_DIR>/:
  1. Resolve the matching foundation-css component JSON:
       <FOUNDATION_COMP_DIR>/<component>/<component>.json
  2. Parse the JSON and find:
       meta.mapping.selector.web   →  e.g. ".app-button"
  3. Store in COMPONENT_SELECTOR_MAP:
       { "button": ".app-button", "anchor": ".app-anchor", ... }
  4. If JSON not found or no selector field → use fallback from HARDCODED_FALLBACKS
```

**Fallback map (used only when foundation JSON is missing or has no selector):**

| Component | Fallback Selector |
|---|---|
| `accordion` | `.app-accordion` |
| `anchor` | `.app-anchor` |
| `badge` | `.app-badge` |
| `button` | `.app-button` |
| `button-group` | `.app-button-group` |
| `cards` | `.app-card` |
| `container` | `.app-container-default` |
| `icon` | `.app-icon` |
| `label` | `.app-label` |
| `list` | `.app-list` |
| `page-header` | `.app-page-header` |
| `panel` | `.app-panel` |
| `picture` | `.app-picture` |
| `popover` | `.app-popover` |
| `tabs` | `.app-tabs` |
| `tile` | `.app-tile` |
| `wizard` | `.app-wizard` |

**Result — `COMPONENT_SELECTOR_MAP`:**

```python
COMPONENT_SELECTOR_MAP = {
    "button":       ".app-button",       # from foundation button.json  meta.mapping.selector.web
    "anchor":       ".app-anchor",       # from foundation anchor.json  meta.mapping.selector.web
    "label":        ".app-label",        # from foundation label.json   meta.mapping.selector.web
    "cards":        ".app-card",         # from foundation cards.json   meta.mapping.selector.web
    # ... one entry per folder in VARIANT_COMP_DIR
}
```

**This map is the sole source of truth for variant detection in STEP 8.**

### STEP 3 · Extract Global Tokens from style.css

Read `<THEME_DIR>/style.css`. Parse the `:root {}` block and extract all CSS custom properties.

#### Auto-classification by variable name pattern

| Pattern in variable name | Token category |
|---|---|
| `*color*`, `*primary*`, `*secondary*`, `*bg*`, `*text*`, `*border*`, `*danger*`, `*success*`, `*warning*`, `*info*` | **Color** |
| `*font*`, `*size*`, `*weight*`, `*line-height*`, `*letter-spacing*` | **Typography** |
| `*gap*`, `*margin*`, `*padding*`, `*space*`, `*radius*`, `*radius*` | **Spacing** |

#### Skip list

Skip variables whose values contain `color-mix(`, `calc(`, or `var(` — these are derived values
that depend on other variables and cannot be expressed as standalone foundation overrides.

### STEP 4 · Match Extracted Tokens Against Foundation

For each extracted token, determine whether it overrides a known foundation semantic token or is
a project-specific custom value.

| Match type | Condition | Action |
|---|---|---|
| **Foundation override** | Variable name contains a semantic keyword (primary, secondary, error, success, warning, info, surface, on-surface, outline) | Map to corresponding foundation path |
| **Custom token** | No semantic match | Keep value as-is in JSON |

### STEP 7.5 · Extract Icon Fonts + Create icon.css and theme-style.css

This step produces two files:
- **`icon.css`** — contains ONLY the icomoon icon CSS (no `@import`)
- **`theme-style.css`** — font `@import` + `:root` + component CSS for the 11 core components (button, label, anchor, cards, popover, container, panel, form, list, picture, tile) + all `@keyframes` animation blocks

#### 7.5.1 — Locate Icon Font Files

Search for `icomoon.*` in:

```
<THEME_DIR>/
<THEME_DIR>/icon-fonts/
<THEME_DIR>/fonts/
```

Copy found files to `<DT_DIR>/custom-icon/`:

```bash
cp <THEME_DIR>/icon-fonts/icomoon.eot  <DT_DIR>/custom-icon/icomoon.eot
cp <THEME_DIR>/icon-fonts/icomoon.ttf  <DT_DIR>/custom-icon/icomoon.ttf
cp <THEME_DIR>/icon-fonts/icomoon.woff <DT_DIR>/custom-icon/icomoon.woff
cp <THEME_DIR>/icon-fonts/icomoon.svg  <DT_DIR>/custom-icon/icomoon.svg
```

#### 7.5.2 — Extract Icon CSS Blocks from style.css

Identify and collect these three CSS block types for icon.css output:

| Block | Pattern | Example |
|---|---|---|
| **@font-face** | `@font-face { font-family: 'icomoon'; ... }` | Full block including `src:` lines |
| **Base selector** | `.wm-app [class^="pr-"], .wm-app [class*=" pr-"] { ... }` | All shared icon properties |
| **Icon definitions** | `.wm-app .pr-<name>:before { content: "\e..."; }` | One rule per icon |

**URL rewrite rule for @font-face src lines:**

```
url('icon-fonts/icomoon.eot?xxx')    →   url('custom-icon/icomoon.eot')
url('icon-fonts/icomoon.ttf?xxx')    →   url('custom-icon/icomoon.ttf')
url('icon-fonts/icomoon.woff?xxx')   →   url('custom-icon/icomoon.woff')
url('icon-fonts/icomoon.svg?xxx')    →   url('custom-icon/icomoon.svg')
```

Strip query-string suffixes (e.g., `?mdouv4`, `?xxx`) from all URLs.

#### 7.5.3 — Write icon.css

Path: `<DT_DIR>/icon.css`

**icon.css contains ONLY:**
1. `@font-face` block for icomoon (with updated URLs)
2. Base selector block `.wm-app [class^="pr-"], .wm-app [class*=" pr-"]`
3. All individual `.wm-app .pr-*:before` rules

> **No `@import` in icon.css.** Font family imports belong in `theme-style.css`.

**icon.css structure:**

```css
/* ============================================================
 * Custom Icon Font: icomoon
 * Source: themes/<THEME_NAME>/icon-fonts/
 * ============================================================ */

@font-face {
  font-family: 'icomoon';
  src: url('custom-icon/icomoon.eot');
  src: url('custom-icon/icomoon.eot#iefix') format('embedded-opentype'),
       url('custom-icon/icomoon.ttf') format('truetype'),
       url('custom-icon/icomoon.woff') format('woff'),
       url('custom-icon/icomoon.svg#icomoon') format('svg');
  font-weight: normal;
  font-style: normal;
  font-display: block;
}

/* Icon base styles — applies to all .pr-* classes */
.wm-app [class^="pr-"],
.wm-app [class*=" pr-"] {
  font-family: 'icomoon' !important;
  speak: never;
  font-style: normal;
  font-weight: normal;
  font-variant: normal;
  text-transform: none;
  line-height: 1;
  -webkit-font-smoothing: antialiased;
  -moz-osx-font-smoothing: grayscale;
}

/* Icon definitions */
.wm-app .pr-token:before { content: "\e95a"; }
.wm-app .pr-arrow-dl:before { content: "\e94d"; }
.wm-app .pr-pages:before { content: "\e94b"; }
/* ... all .pr-* rules ... */
.wm-app .pr-prefab-v:before { content: "\e939"; font-size: 19px; }
```

> **icon.css must NOT contain:** `@import` statements, component variant CSS, `:root` variables,
> utility classes, or any CSS not directly related to the icomoon icon font.

#### 7.5.4 — Write theme-style.css

Path: `<DT_DIR>/theme-style.css`

**theme-style.css = font `@import` + `:root {}` + CSS rules for the 11 core components only.**

It is NOT a full copy of style.css — only the relevant component rules are included.

---

##### THEME_STYLE_COMPONENTS — component selectors to include

| Component | Selectors that trigger inclusion |
|---|---|
| button | `.btn`, `.app-button` |
| label | `.label`, `.app-label` |
| anchor | `.anchor`, `.app-anchor` |
| cards | `.app-card`, `.app-cards` |
| popover | `.popover`, `.app-popover` |
| container | `.app-container`, `.app-container-default` |
| panel | `.panel`, `.app-panel` |
| form | `.form-control`, `.form` |
| list | `.app-list`, `.app-livelist`, `.list` |
| picture | `.picture`, `.app-picture` |
| tile | `.tile`, `.app-tile` |

---

##### Inclusion rules (applied to every rule block in style.css)

A rule block is **INCLUDED** if any of the following match:

| # | Condition | Example |
|---|---|---|
| 1 | It is `@import` and `FONT_IMPORT_URL` is set | `@import url("...")` |
| 2 | It is `:root {}` | `:root { --my-var: ... }` |
| 3 | It is `@font-face` with a font-family that is NOT `'icomoon'` | Custom non-icon font |
| 4 | The selector directly matches a THEME_STYLE_COMPONENT selector | `.app-button { }` |
| 5 | The selector is a custom-class + component combination | `.dark-btn.app-button { }` |
| 6 | The selector targets a nested child of a component | `.app-button .icon { }`, `.app-card .title { }` |
| 7 | It is `@media` and at least one nested rule satisfies rules 4–6 | `@media (max-width: 768px) { .app-button { ... } }` |
| 8 | It is `@keyframes` (any name) | `@keyframes fadeIn { from { ... } to { ... } }` |

A rule block is **EXCLUDED** if:
- It is `@font-face { font-family: 'icomoon' ... }` — goes to `icon.css` instead.
- It matches `[class^="pr-"]` or `.pr-*:before` — goes to `icon.css` instead.
- It does not reference any THEME_STYLE_COMPONENT selector.

---

##### theme-style.css structure

```css
/* ============================================================
 * Font Family Import (migrated from legacy theme)
 * ============================================================ */
@import url("https://fonts.googleapis.com/css2?family=Inter:...&display=swap");
/* (only present if FONT_IMPORT_URL was confirmed in STEP 3b) */

/* :root variables from original style.css */
:root {
  --primary-color: #FF7250;
  /* ... all root vars ... */
}

/* Component rules (button, label, anchor, cards, popover, container, panel, form, list, picture, tile) */
.wm-app .app-button { ... }
.wm-app .dark-btn.app-button { ... }
.wm-app .app-button .icon { ... }
/* ... all matching rules ... */
```

---

##### Algorithm

```
output = []

Step 1 — Font import (prepend if available):
  IF FONT_IMPORT_URL is set:
    output.append(@import block)

Step 2 — Scan style.css rule by rule:
  For each rule block:
    a. If @font-face with font-family 'icomoon'      → SKIP (icon.css owns this)
    b. If [class^="pr-"] base selector               → SKIP (icon.css owns this)
    c. If .wm-app .pr-*:before rule                  → SKIP (icon.css owns this)
    d. If :root {}                                   → INCLUDE
    e. If @font-face (non-icomoon)                   → INCLUDE
    f. If selector contains any THEME_STYLE_COMPONENT selector
       (direct, combination, or nested child)        → INCLUDE
    g. If @media block containing any rule matching (d)–(f)
                                                     → INCLUDE whole @media block
    h. If @keyframes (any animation name)            → INCLUDE verbatim
    i. Otherwise                                     → EXCLUDE

Step 3 — Write output to <DT_DIR>/theme-style.css
```

### STEP 8 · Extract Component Variants → JSON

Extract custom component variant CSS from style.css and produce structured JSON override files.

#### 8.0 — Supported Components

Components eligible for JSON variant extraction are the **folders in `<VARIANT_COMP_DIR>/`**.
Read the list dynamically at runtime:

```
accordion, anchor, badge, button, button-group, cards, container,
icon, label, list, page-header, panel, picture, popover, tabs, tile, wizard
```

Only these components produce JSON files. All other component CSS is skipped (it stays
visible in `theme-style.css` for manual review).

#### 8.1 — Load Component Selector Map

For each supported component, resolve its CSS selector from foundation-css:

```
<FOUNDATION_COMP_DIR>/<component>/<component>.json
  → meta.mapping.selector.web   →  e.g.  ".app-button"
```

**Python reference:**

```python
import json
from pathlib import Path

COMPONENT_SELECTOR_MAP = {}
for comp_dir in VARIANT_COMP_DIR.iterdir():
    if not comp_dir.is_dir():
        continue
    component = comp_dir.name
    json_path = FOUNDATION_COMP_DIR / component / f'{component}.json'
    selector = None
    if json_path.exists():
        data = json.loads(json_path.read_text())
        # Walk the JSON tree to find selector.web
        def find_web_selector(obj):
            if isinstance(obj, dict):
                if 'selector' in obj and isinstance(obj['selector'], dict):
                    return obj['selector'].get('web')
                for v in obj.values():
                    r = find_web_selector(v)
                    if r:
                        return r
            return None
        selector = find_web_selector(data)
    if selector:
        COMPONENT_SELECTOR_MAP[component] = selector
    else:
        COMPONENT_SELECTOR_MAP[component] = HARDCODED_FALLBACKS.get(component)
```

#### 8.2 — Variant Detection Rule

A CSS rule in style.css is a **custom variant** for component `C` if ALL of these hold:

```
1. Selector starts with  .wm-app
2. Selector contains     <COMPONENT_SELECTOR_MAP[C]>        (e.g. .app-button)
3. Selector also contains a separate custom class            (e.g. .dark-btn)
   that is NOT the component selector itself
4. The rule block contains at least one CSS property declaration
```

**Pattern (pseudocode):**

```
.wm-app  .{CUSTOM_CLASS}.{COMPONENT_SELECTOR}  { ... }
          ↑ variant name   ↑ anchors component
```

**Concrete examples:**

```css
/* ✅ VARIANT — .dark-btn is the custom class; .app-button anchors to "button" */
.wm-app .dark-btn.app-button {
    background: #000;
    color: #fff;
}

/* ✅ VARIANT — .custom-list is the custom class; .app-list anchors to "list" */
.wm-app .custom-list.app-list {
    background: #f5f5f5;
}

/* ✅ VARIANT — .external is the custom class; .app-anchor anchors to "anchor" */
.wm-app .external.app-anchor {
    color: #0066cc;
}

/* ❌ NOT A VARIANT — .app-button alone (no custom class) → skip */
.wm-app .app-button {
    color: red;
}

/* ❌ NOT A VARIANT — component selector not present → skip (utility class) */
.wm-app .card-wrapper {
    border-radius: 8px;
}
```

**Variant name extraction:**

```python
# Given selector: ".wm-app .dark-btn.app-button"
# component_selector = ".app-button"
# Extract all class tokens except "wm-app" and the component selector class
variant_name = (all class tokens in selector)
               .excluding("wm-app")
               .excluding(component_selector.lstrip('.'))
               .first()   →  "dark-btn"
```

#### 8.3 — Scan style.css for Variants

```python
# Parse all CSS rule blocks from style.css (skip :root, @font-face, @media, @keyframes — those go to theme-style.css)
for selector, props in parse_css_rules(style_css):
    if not selector.strip().startswith('.wm-app'):
        continue
    for component, comp_selector in COMPONENT_SELECTOR_MAP.items():
        if comp_selector in selector:
            # Extract custom class name
            variant_name = extract_custom_class(selector, comp_selector)
            if variant_name and props.strip():
                record_variant(component, variant_name, selector, props)
            break
```

## Decision Tree: What Goes Where

```
style.css CSS rule
│
├── Is it @font-face { font-family: 'icomoon' }?
│     └── YES → icon.css only. Excluded from theme-style.css.
│
├── Is it .wm-app [class^="pr-"] or .wm-app .pr-*:before?
│     └── YES → icon.css only. Excluded from theme-style.css.
│
├── Is it @import and FONT_IMPORT_URL confirmed?
│     └── YES → theme-style.css only (first line). NOT in icon.css.
│
├── Is it @keyframes (any name)?
│     └── YES → theme-style.css only (included verbatim). NOT in icon.css, NOT in JSON.
│
├── Is it :root { ... }?
│     ├── → theme-style.css (kept verbatim)
│     └── Extract tokens for global JSON files (color/typography/spacing)
│
├── Is it .wm-app .<custom-class>.<COMPONENT_SELECTOR> { ... }?
│     ├── YES and component is in variant-components/
│     │     ├── → JSON to overrides/components/<c>/<c>.json
│     │     └── → theme-style.css (kept verbatim for reference)
│     └── YES but component NOT in variant-components/
│           └── → theme-style.css only (if selector is in THEME_STYLE_COMPONENTS)
│
├── Does the selector contain any THEME_STYLE_COMPONENT selector
│   (direct, nested child, or combination)?
│     └── YES → theme-style.css (kept verbatim)
│
└── All other rules (utility classes, unsupported components, etc.)
      └── EXCLUDED — not written to any output file
```

## FAQ

| Question | Answer |
|---|---|
| **Where does component variant CSS go now?** | JSON only in `overrides/components/`. The raw CSS for the 11 core components also appears in `theme-style.css` for reference. There is no longer a `custom.css`. |
| **Where does icon CSS go?** | `icon.css` only. No `@import`, no component CSS, nothing else belongs in `icon.css`. |
| **What is `theme-style.css`?** | A filtered output containing: font `@import` (if confirmed), `:root` variables, CSS rules for button, label, anchor, cards, popover, container, panel, form, list, picture, tile — including nested children and custom-class combinations — and all `@keyframes` animation blocks from style.css. Rules for other selectors are excluded. |
| **Where do `@keyframes` animation blocks go?** | Into `theme-style.css` verbatim, placed after component CSS rules. They are never written to `icon.css`, `app.override.css`, or any JSON file. |
| **Is `custom.css` still created?** | No. `custom.css` is replaced by `icon.css` (icomoon icons) and `theme-style.css` (component CSS). |
| **Where does the font family `@import` go?** | `theme-style.css` — it is the first line of that file. It does NOT go in `icon.css`. |
| **When is `app.override.css` created?** | Never by this skill. Studio auto-generates it from the JSON token files on first open. |
| **What if a component has no variants?** | No JSON file is created for that component. Only components with detected `.wm-app .<custom>.<selector>` patterns get JSON files. |
| **What if I can't express a CSS value as a token reference?** | Use the raw value as a string literal in the JSON `"value"` field. The design system will use it directly. |
| **Can I re-run the skill?** | Yes. JSON files are merged (new variants added as siblings), `icon.css` is appended with a separator, and `theme-style.css` is always regenerated from the current `style.css` (filtered to the 11 core components). |
